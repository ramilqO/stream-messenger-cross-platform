# ADR: Внедрение Reactive Event Bus на базе RxJS

**Статус:** Принято  
**Дата:** 2 июня 2026 г.

## Контекст и проблема

В приложении существует потребность в обмене данными между независимыми бизнес-модулями (например, модуль
авторизации, аналитики, уведомлений). Использование прямых импортов и передача ссылок между модулями создает
сильную связность (tight coupling), что затрудняет масштабирование, тестирование и поддержку кода.

## Решение

Реализовать централизованную шину событий (**Event Bus**) на базе библиотеки **RxJS**, используя паттерн
`Subject`.

- Шина предоставляет интерфейс `IEventBus` с методами `publish` и `subscribe`.
- Все события типизированы через `DomainEventMap`.
- Фильтрация событий происходит на уровне `pipe` с использованием оператора `filter`.

## Последствия

### Положительные (Pros)

- **Слабая связность:** Модули взаимодействуют только через шину, не имея прямых зависимостей друг от друга.
- **Масштабируемость:** Возможность подключения новых подписчиков на существующие события без модификации кода
  издателя.
- **Типизация:** Использование TypeScript обеспечивает строгий контракт между издателем и подписчиком.
- **Реактивность:** Возможность использования всего стека RxJS (операторы `debounceTime`, `buffer`, `delay` и
  т.д.) для сложной логики обработки.

### Отрицательные (Cons)

- **Неявные связи:** Усложняется трассировка потока выполнения («кто отправил это событие?»).
- **Утечки памяти:** Требуется дисциплина при управлении подписками (обязательный вызов `unsubscribe`).
- **Синхронность:** Выполнение `publish` блокирует поток до завершения работы всех подписчиков, если не
  применяется асинхронная обработка внутри них.

## Правила использования

1.  **Доменные события:** В шину передаются только бизнес-факты (например, `UserLoggedIn`, `OrderPlaced`).
    События интерфейса (клики, наведение мыши) должны обрабатываться локально в рамках компонентов.
2.  **Жизненный цикл:** Все подписки должны быть привязаны к жизненному циклу компонента/сервиса. Обязателен
    возврат и вызов функции `unsubscribe`.
3.  **Инкапсуляция:** `Subject` является `private` полем класса. Внешним модулям предоставляется только метод
    `subscribe` (через интерфейс).

## Альтернативы

- **EventEmitter (Node.js style):** Отсутствие мощных инструментов трансформации потоков, затрудняющих
  обработку сложных последовательностей событий.
- **Глобальный Store (Zustand/Redux):** Избыточное решение для передачи «сигнальных» событий (Event Bus лучше
  подходит для уведомлений, чем для хранения данных).
- **Prop Drilling (Прямые колбэки):** Приводит к усложнению архитектуры компонентов и нарушению принципов
  инкапсуляции.
